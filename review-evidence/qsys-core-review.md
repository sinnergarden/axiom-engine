# QSYS Core shared rolling kernels

The task adds four explicit operators to the existing plan and its scalar and packed execution paths. Existing operator names, parameter schemas and semantic revision strings remain unchanged, so unaffected saved mathematical identities remain valid. New dependent recipes acquire their new operator revisions through the existing resolver. No data reads, preparation, training or publication are authorized here.

Before implementation, reviewed plan admission, dependency expansion, packed column lifetime and rolling provenance. All operators use the original ordered session/observation window, with explicit endpoints, minimum count and missing policy. Correlation admits paired observations only. Regression uses original window positions (1-based), with a shared centered least-squares kernel returning slope, R-square and final-position residual. Quantiles use linear interpolation; extrema use original positions and explicit first/last ties. Zero variance is explicit missing/reject. Availability and source lineage merge every window dependency, including missing observations, and unavailable inputs retain existing issue propagation.

The packed path gathers each parent window once across securities and reduces provenance across the matrix; it must not repeatedly slice the full window for every security. Scalar and packed paths share numeric kernels. Numeric regression reuse is call-local and bounded; no data-source expansion or external I/O is added. Focused independent expected-value tests precede static review and any parent-owned integration. Real preparation remains blocked outside this subtask.

## Implemented contract and acceptance

All new operators have version `1`. Common parameters are `window` and `min_periods` positive integers (`min_periods <= window`), boolean `inclusive_current`, and `missing=skip|propagate`. History closure adds `window - inclusive_current` to the maximum parent depth. Partial history preserves the available ordered suffix; full history requires the complete dependency window.

`rolling_corr(x,y)` additionally requires `zero=missing|reject`, uses paired valid observations and returns dimensionless Pearson correlation. `rolling_regression(y)` additionally requires `output=slope|rsquare|resi` and `zero=missing|reject`; slope and residual preserve y's unit per one observation step, while R-square is dimensionless. Fewer than two observations is undefined; zero policy governs an undefined fit and constant-response R-square. Constant-response slope and residual are zero. A missing final y leaves the residual missing even when earlier observations fit successfully. `rolling_quantile(x)` requires `quantile` in [0,1] and `interpolation=linear`, preserving input units. `rolling_idx(x)` requires `extreme=max|min`, `ties=first|last`, and `index_base=1`, returning a dimensionless position measured from the oldest available window entry. Missing entries retain their positions.

The shared regression cache retains at most 65,536 input positions and is discarded after each execution. It reuses all three outputs when matching windows remain resident; large scopes can evict them and recompute, so this is not a claim of full-history throughput optimization. Packed windows gather each parent matrix once per output row, and extract individual security vectors without repeated full-window reads. Existing packed array workspace accounting and scalar/batch policies are unchanged. No global cache or new executor was introduced.

Focused verification used Python 3.12 and synthetic fixtures only. The final focused run passed 36 tests across `test_qsys_rolling`, `test_feature_columns`, `test_conformance`, and `test_feature_plan_batch`. The earlier 40-test run additionally passed `test_feature_library_metadata` and `test_feature_library_security_blocks`; subsequent edits only added provenance/degenerate tests and made the new regression zero policy consistent for underdetermined fits. Independent arithmetic expectations include slope 1.4, R-square .98, residual -.1, interpolated quantile 1.75, and perfect negative correlation. Tests compare numerical values, missing reasons, maximum availability and source unions between transports. They also cover empty exclusive partial windows, full-history rejection and nested lag/window history, and prove the shared regression computes once for three sibling outputs in each transport.

Static review after the tests found that the first standard-library memoization import violated Core's import admission rule; it was replaced with a small bounded call-local dictionary. Review also checked that old `rolling` parameters and revision `r0_rolling_v1` are untouched, while the existing revision registry automatically assigns separate tags to each new operator. Only recipes containing new nodes gain new mathematical identities. Existing artifacts need no migration; parent integration must build new catalog recipes against these operators, then perform its authorized small real validation before any larger preparation. No real end-to-end throughput or data-coverage claim is made here.

## Parent review: packed temporary budget correction

Parent review identified that the new packed regression tuple cache and window gathers were outside `max_working_bytes`. The follow-up removes the tuple cache entirely from packed execution. Scalar execution retains its bounded call-local cache. Packed execution still calls the same regression math, but sibling outputs may recompute it; this is an explicit performance tradeoff for bounded workspace without a framework change.

Before any new-family window allocation, packed execution now reserves value/validity matrices for every parent, the largest provenance gather, reduction vectors, and a conservative per-window-position allowance for Python vectors, indices, sorting and centered numeric intermediates. It drops the reservation only after deleting the temporary window objects. The reservation scales with actual window rows, security width and parent count. Original `rolling`, CS and other operators receive no new charge. This is a conservative allocation budget, not an RSS measurement.

The added 256-position test measures the reported peak from an admitted execution, proves peak-minus-one rejects before the numeric kernel is entered, admits the same work at the reported peak, checks exact value/validity bytes and scalar parity, and forbids packed cache creation with a test patch. The final focused run passed 38 tests across QSYS rolling, packed columns, conformance and batch paths. `git diff --check` passed. No real data or preparation was run.
